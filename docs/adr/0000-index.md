## 关于框架的“钟摆效应”与“造轮子学习法”

开发者同时在维护多个 AI 项目，但在技术选型上展现了极其清醒的“场景决定论”：

- **`task-planner`** 因复杂的图状态与条件边，拥抱了 `LangGraph`。
- **`deepdream-agent`** 因算法工程化，使用了 `Gradio` 与 `LangGraph`。
- **`nano-harness`** 作为最底层、最锻炼底子的项目，**反其道而行之**：拒绝了所有重型图编排框架，拒绝了官方 MCP SDK，纯手写 `while` 循环、纯手写协议适配器。

这不是技术倒退，而是一种刻意的**“造轮子学习法”**。我们相信，只有亲手实现过控制流的流转、亲手解析过 JSON-RPC 协议，才能真正看清大模型应用底层的运转机制。这也正是 `nano-harness` 得以保持极致轻量、且无惧任何黑盒魔法的底气所在。
